## Issues at a Glance

### CRITICAL (Fix Immediately)
1. **Payout Implementation Incomplete** (cron/mod.rs:271–285)
   - Payouts marked "completed" WITHOUT calling Stripe Transfer API
   - Sellers paid $0 while orders show paid
   - Fix: Implement stripe_create_transfer() call with Idempotency-Key

2. **Float Math in Shipping** (shipping_calc/mod.rs)
   - All calculations in f64 dollars → rounding errors accumulate
   - Sellers charged/refunded wrong amounts
   - Fix: Convert to i64 cents, divide only at display layer

3. **Rate Limiter X-Forwarded-For Bypass** (shared/rate_limiter.rs)
   - Trusts X-Forwarded-For from any source
   - Attacker spoofs IP → rate limits useless
   - Fix: Only trust from 127.0.0.1 (Caddy proxy)

### HIGH (Fix Within Sprint)
4. **Missing DB Indexes** (ratings.rs, questions.rs, favorites)
   - No indexes on (productId, createdAt), (userId, productId)
   - N+1 queries, slow pagination, high DB load
   - Fix: Add SurrealDB DEFINE INDEX statements in new shared/indexes.rs

5. **Refund + Payout Race Condition** (orders/refunds.rs:333–336)
   - Payout processes while refund tries to reverse → ledger inconsistency
   - Partially fixed (payout status check), needs transaction isolation
   - Fix: Add SurrealDB transaction with payoutLocked flag

6. **Subscription Double-Create** (payments/subscriptions.rs:200–230)
   - Race condition: two simultaneous requests create duplicates
   - User charged twice
   - Fix: Check for active subscription BEFORE creation

7. **Password Reset Token Reuse** (ob-auth/routes.rs)
   - Token valid forever → attacker can reset password anytime
   - Fix: Mark token used immediately after verification

8. **TOTP Brute-Force Vulnerability** (ob-auth/routes.rs)
   - No rate limiting on TOTP attempts
   - 6-digit code crackable (~1M attempts)
   - Fix: Max 5 attempts per 15 minutes, lock MFA after exceeded

### MEDIUM (Quality Improvements)
9. **OAuth State Nonce Memory Leak** (ob-auth/routes.rs)
   - In-memory HashMap grows unbounded → memory exhaustion DoS
   - Fix: Use DB storage or add TTL cleanup cron job

10. **Phone Number Validation** (addresses/mod.rs)
    - Invalid phone numbers break SMS notifications
    - Fix: Add E.164 format validation (+14165551234)

11. **Postal Code Validation** (addresses/mod.rs)
    - Invalid postal codes fail shipping lookups
    - Fix: Enforce Canadian format [A-Z]\d[A-Z] \d[A-Z]\d

12. **Multi-Seller Warehouse Validation** (shipping_calc/mod.rs)
    - Shipping calculated without verifying seller has warehouse
    - Fix: Validate warehouseAddress before calculation
